# 5 · 6502 demo dataset

Source of truth: the **6502.org opcode chart** and the original **MOS 6502 datasheet**. We document the **original NMOS 6502** — not the 65C02, which is an M3 variant (it adds `BRA`, `PHX`/`PHY`/`PLX`/`PLY`, `STZ`, `TRB`/`TSB`; a `JMP (abs,X)` mode; three extra `BIT` modes; a new `(zp)` indirect mode on `ADC` `AND` `CMP` `EOR` `LDA` `ORA` `SBC` `STA`; and it fixes the NMOS `JMP ($xxFF)` page-wrap bug, where the high byte was fetched from `$xx00` instead of the next page).

## Scope

- **56 canonical mnemonics.** No aliases are needed for the NMOS 6502 — every documented opcode maps to exactly one mnemonic, and `aliases` stays `[]` for all 56. (`ASR` and `NOOP` are *not* 6502 mnemonics: `ASR` belongs to other 8-bit families, `NOOP` is not a MOS spelling. Do not invent them.)
- **151 documented opcodes** (of 256). The remaining 105 are *undocumented/illegal* opcodes: **out of scope for v1**; a read-only appendix could be added in M3.
- **13 addressing modes** — the full official set (mode names below are the `modes[].name` vocabulary in [03-data-model.md](./03-data-model.md)):

| `modes[].name` | Assembly form | Bytes | Notes |
|---|---|---|---|
| `implicit` | `CLC` | 1 | Opcode only; no operand |
| `accumulator` | `ASL A` | 1 | `ASL` `LSR` `ROL` `ROR` only |
| `immediate` | `LDA #$44` | 2 | |
| `zero_page` | `LDA $44` | 2 | |
| `zero_page_x` | `LDA $44,X` | 2 | Wraps within page 0 |
| `zero_page_y` | `LDX $44,Y` | 2 | `LDX` and `STX` only |
| `relative` | `BNE label` | 2 | Branches only; signed −128…+127 |
| `absolute` | `LDA $4400` | 3 | |
| `absolute_x` | `LDA $4400,X` | 3 | |
| `absolute_y` | `LDA $4400,Y` | 3 | |
| `indirect` | `JMP ($4400)` | 3 | `JMP` only. NMOS bug: if the low byte is `$FF`, the high byte of the target is fetched from `$xx00`, not the next page |
| `indexed_indirect` | `LDA ($44,X)` | 2 | "(zp,X)" — pointer picked from page 0 |
| `indirect_indexed` | `LDA ($44),Y` | 2 | "(zp),Y" — pointer from page 0, then +Y |

`indexed_indirect` and `indirect_indexed` are **different modes** with different cycle counts and different page-crossing behaviour. Never merge them.

## Flag semantics to encode correctly

- Flag register layout **`NV-BDIZC`** (bit 7 → bit 0; bit 5 is unused and reads as 1).
- `flags` lives on the **instruction**, not the mode — on the NMOS 6502 every mode of a mnemonic touches the same flags. If a future variant breaks that (65C02 `BIT #` sets only `Z`), add an optional `modes[].flags` override then, not now.
- **Never list `B` in `flags`.** `B` (break) is not a real register bit; it only exists in the status byte pushed to the stack. `BRK` pushes it set, `PHP` pushes it set, `PLP`/`RTI` load whatever was pushed. Model that in `description`, not in `flags`.
- Examples: `ADC` ⇒ `N V Z C` · `AND` ⇒ `N Z` · `CMP` ⇒ `N Z C` · `ASL` ⇒ `N Z C` · `PLP`/`RTI` ⇒ `N V D I Z C` (all restored from the stack).
- `BIT` ⇒ `N V Z`: **`N` ← bit 7 of the operand, `V` ← bit 6 of the operand, `Z` ← `A AND operand`**. This is the same on the NMOS 6502 and the 65C02 — it is *not* a variant difference. (The 65C02 only adds modes, and its `BIT #imm` affects `Z` alone.)
- `ADC`/`SBC` read carry *in* before computing, and write carry *out* from the result. `SBC` uses carry as "not borrow".
- `D` (decimal) changes the `ADC`/`SBC` *result* to BCD. On the **NMOS 6502 the `N`, `V` and `Z` flags are invalid in decimal mode** — undocumented behaviour, `Z` does not reliably match the accumulator. (The 65C02 makes `N` and `Z` match the BCD result, at the cost of one extra cycle; `V` has no useful meaning in decimal mode on any of them, since BCD is unsigned.) Say this explicitly in both `description`s — do not claim the flags stay binary.
- `SBC` treats carry as **not-borrow**: with carry set, `SBC n` computes `A − n`; with carry clear it subtracts one more.

## Cycle semantics to encode correctly

Page-crossing costs are **not uniform across modes**. Encode per mode, in `modes[].cycles`:

| Mode | Penalty |
|---|---|
| `absolute_x`, `absolute_y` | **+1** when the effective address crosses a page — for *read* instructions only (`LDA` `LDX` `LDY` `ADC` `SBC` `AND` `ORA` `EOR` `CMP`). |
| `indirect_indexed` `(zp),Y` | **+1** on page cross, reads only. |
| `indexed_indirect` `(zp,X)` | **Never.** Always 6 cycles. |
| `STA absolute_x`/`absolute_y`/`(zp),Y` | **Never** — the write always pays the fixup: fixed 5, 5 and 6. |
| Read-modify-write `absolute_x` (`ASL` `LSR` `ROL` `ROR` `INC` `DEC`) | **Never** — fixed 7. |
| `relative` (branches) | **+1** if the branch is taken, **+2** if taken *and* the target is on another page. |

Write these inline as strings, e.g. `"4 (5 on page cross)"` for `LDA $4400,X`, `"5"` for `STA $4400,X`, `"2 (3 if taken, 4 if taken across a page)"` for `BNE`.

## Mnemonic → category

Fixed. The authoring step copies this table; it does not re-derive it. Vocabulary defined in [03-data-model.md](./03-data-model.md).

| `category` | Meaning | Mnemonics | n |
|---|---|---|---|
| `load_store` | Memory ↔ register | `LDA`, `LDX`, `LDY`, `STA`, `STX`, `STY` | 6 |
| `transfer` | Register → register | `TAX`, `TAY`, `TSX`, `TXA`, `TXS`, `TYA` | 6 |
| `stack` | Push/pull | `PHA`, `PHP`, `PLA`, `PLP` | 4 |
| `arithmetic` | Add, subtract, compare, inc/dec | `ADC`, `SBC`, `CMP`, `CPX`, `CPY`, `INC`, `INX`, `INY`, `DEC`, `DEX`, `DEY` | 11 |
| `logic` | Bitwise | `AND`, `ORA`, `EOR`, `BIT` | 4 |
| `shift` | Shift and rotate | `ASL`, `LSR`, `ROL`, `ROR` | 4 |
| `branch` | Conditional, `relative` mode | `BCC`, `BCS`, `BEQ`, `BMI`, `BNE`, `BPL`, `BVC`, `BVS` | 8 |
| `jump` | Unconditional transfer of control | `JMP`, `JSR`, `RTS` | 3 |
| `flag` | Set/clear a status bit | `CLC`, `CLD`, `CLI`, `CLV`, `SEC`, `SED`, `SEI` | 7 |
| `system` | Interrupt and no-op | `BRK`, `NOP`, `RTI` | 3 |
| | | **total** | **56** |

`TSX`/`TXS` are register transfers, not `stack` — they move the stack *pointer*, they do not push or pull. `CMP`/`CPX`/`CPY` are `arithmetic`: they are a subtract that discards the result.

## Work split (for the data authoring step)

1. Transcribe all 151 opcodes as a flat `(opcode, mnemonic, mode, bytes, cycles)` table — one opcode per row, `opcode` is a scalar.
2. Group by mnemonic (⇒ 56 groups), attach `summary`/`description`/`examples` (2–4 sentences each; flag effects spelled out; one worked example per mode family where useful).
3. Run the invariant checks from [03-data-model.md](./03-data-model.md) (counts, opcode uniqueness, `bytes`, `cycles`, no `B` in `flags`).
